# SecCheck — курсовая работа

Консольная программа контроля работоспособности антивируса (АВ) и межсетевого экрана (МЭ)
в Linux с systemd. Курсовая по дисциплине «Методы и средства защиты информации
в компьютерных сетях» (МТУСИ, кафедра ИБ). ТЗ и пошаговые алгоритмы модулей: `docs/SPEC.md`.
Прочитай его целиком перед любой работой над кодом.

## Кто и как будет пользоваться кодом

- Автор — студент. На защите он должен объяснить каждую строку. Поэтому код простой
  и явный: функции и константы, без классов, декораторов, хитрых однострочников и лишних
  абстракций. Ничего сверх описанного в SPEC.md не добавляй.
- Исходники целиком пойдут в приложение к пояснительной записке. Нужны docstring у каждого
  модуля и функции и комментарии к неочевидным местам, **на русском языке**.
- Алгоритм каждого модуля проверок должен совпадать с пошаговым алгоритмом из SPEC.md
  (по нему рисуются блок-схемы). Если меняешь логику, обнови и алгоритм в SPEC.md
  и скажи об этом.

## Структура

```
main.py             # меню, словарь results, отчёт (M5)
common.py           # run_cmd(), is_root(), os_info(), load_config(), константы статусов
check_network.py    # M1
check_presence.py   # M2 + load_products() (загрузка и проверка products.json)
products.json       # список продуктов для M2 (подменяется флагом --products PATH)
config.json         # образец настроек; рабочий файл — /etc/seccheck/config.json (--config)
check_firewall.py   # M3
check_antivirus.py  # M4
install.sh, uninstall.sh, README.md, docs/SPEC.md
```

## Жёсткие ограничения

- **Платформа:** Linux с systemd. Никакой логики под конкретный дистрибутив. Только консоль.
- **Python 3.7+.** Запрещено: `:=`, `match`, `f"{x=}"`, позиционные `/` параметры,
  `dict[str, int]`/`list[str]` вне аннотаций, `functools.cache`, `str.removeprefix`,
  `zoneinfo`, `tomllib`. В каждом `.py` после docstring стоит
  `from __future__ import annotations`; в аннотациях используй `typing.List` и т. п.
- **Только стандартная библиотека.** Никаких psutil, rich, click, colorama.
- **Программа ничего не меняет в системе.** Не создаёт правила МЭ, не трогает службы.
  Единственное, что она пишет, — тестовый файл EICAR в собственный подкаталог
  (`mkdtemp` внутри `eicar_dir` или системного временного каталога); файл и подкаталог
  удаляются в `finally`, сам `eicar_dir` и чужие файлы в нём не трогаются. Команды тестового правила МЭ есть только в README.md.
- Строка EICAR **никогда** не хранится целиком: ни в исходниках, ни в документации,
  ни в сообщениях коммитов. Только частями, которые склеиваются при выполнении.
- Внешние команды вызываются только через `common.run_cmd()`: с таймаутом, с `LC_ALL=C`,
  без `shell=True`.
- Нехватка прав — не падение, а понятное сообщение в подробностях проверки.
- `sys.dont_write_bytecode = True` в `main.py` стоит до импорта модулей проекта.
- **`products.json` читается с правами root**, его может подменить пользователь
  (`--products`). Поэтому в формате нет и не должно быть полей с командами или
  аргументами: имена служб только передаются в `systemctl is-active` через `run_cmd`
  (после проверки regex из SPEC.md), пути только проверяются через `os.path.exists`.
  Неизвестные поля — ошибка. Новое поле в формате — только по решению автора, с правкой
  `load_products`, README.md и SPEC.md.
- **Настройки только в `config.json`**: узлы, порты, таймауты. Констант настроек
  в модулях и значений по умолчанию в коде нет; без файла программа не запускается.
  Все ключи обязательны, неизвестные — ошибка. Новый ключ — правка `CONFIG_SCHEMA`
  в `common.py`, `config.json`, README.md («Настройки») и SPEC.md (раздел 6).
  Имена узлов проверяются regex: они передаются в `ping`, запущенный от root.
- Имена служб и пути с `"verified": false` в `products.json` не проверены на реальной
  системе. Не выдавай их за точные.

## Соглашения

- Идентификаторы на английском; тексты для пользователя, docstring и комментарии — на русском.
- PEP 8, длина строки до 100. Аннотации типов у функций.
- Каждая проверка — функция `run(cfg)`, где `cfg` — её секция настроек; возвращает
  `(статус, [итог, подробности...])`. M2: `check_presence.run(cfg, products)`.
  В `main.py` для каждой проверки есть функция без аргументов, передающая секцию.
- Если не уверен в формате вывода утилиты или имени службы, не угадывай: оставь
  `# TODO(стенд): ...` и попроси автора прислать вывод команды.

## Проверка после изменений

Автоматических тестов нет. После правок:

```bash
for f in *.py; do python3 -m py_compile "$f"; done
# грамматика Python 3.7 (py_compile проверяет только синтаксис текущей версии):
python3 -c "import ast,glob; [ast.parse(open(f).read(), f, feature_version=(3,7)) for f in glob.glob('*.py')]"
```

убедись, что `config.json` проходит `load_config`, `products.json` — `load_products`,
и что строка EICAR целиком не встречается ни в одном файле проекта. Проверки на реальной
системе запускает автор (`sudo ./main.py --config ./config.json`).
