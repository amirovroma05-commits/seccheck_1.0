# SecCheck — курсовая работа

Консольная программа контроля работоспособности антивируса (АВ) и межсетевого экрана (МЭ)
на Astra Linux SE. Курсовая по дисциплине «Методы и средства защиты информации в компьютерных
сетях» (МТУСИ, кафедра ИБ). Полное ТЗ, алгоритмы модулей и схемы данных: `docs/SPEC.md`.
Прочитай его целиком перед любой работой над кодом.

## Кто и как будет пользоваться кодом

- Автор — студент. На защите он должен объяснить каждую строку. Поэтому код простой
  и явный: никаких метаклассов, декораторов-фабрик, хитрых однострочников и лишних абстракций
  сверх описанных в SPEC.md.
- Исходники целиком пойдут в приложение к пояснительной записке. Нужны docstring у каждого
  модуля, класса и публичной функции и комментарии к неочевидным местам, **на русском языке**.
- Алгоритм каждого модуля проверок должен совпадать с блок-схемой из SPEC.md (раздел
  «Алгоритм»). Если меняешь логику, обнови и алгоритм в SPEC.md, и скажи об этом.

## Жёсткие ограничения

- **Платформа:** только Astra Linux SE (1.7 и 1.8). Windows и GUI сейчас НЕ делаем, но
  архитектура должна позволять добавить их позже без переписывания модулей (см. SPEC.md, слои).
- **Python 3.7-совместимость.** В Astra SE 1.7 стоит Python 3.7. Запрещено: `:=`, `match`,
  `f"{x=}"`, позиционные `/` параметры, `dict[str, int]`/`list[str]` в рантайме (в аннотациях
  можно только с `from __future__ import annotations` в начале каждого файла),
  `functools.cache`, `str.removeprefix`, `zoneinfo`, `tomllib`.
- **Только стандартная библиотека.** Стенд может быть без интернета и без pip. Никаких
  psutil, rich, click, colorama, pytest. Тесты на `unittest`.
- **Программа ничего не меняет в системе.** Не создаёт и не удаляет правила МЭ, не трогает
  службы. Единственное, что она пишет: тестовый файл EICAR во временный каталог (удаляется
  в `finally`) и отчёты в `reports/`. Команды для создания тестового правила МЭ программа
  только печатает (`--print-fw-rule`).
- Строка EICAR **никогда** не хранится в исходниках целиком, только частями, которые
  склеиваются при выполнении. Иначе антивирус удалит саму программу. Это же касается тестов,
  документации и сообщений коммитов.
- Модули проверок не делают `print` и `input`. Они возвращают `CheckResult`, а вывод делает
  только слой `ui/`.
- Модули проверок не вызывают `subprocess` напрямую, только через методы адаптера
  `adapters/astra.py`.

## Соглашения

- Идентификаторы на английском, все тексты для пользователя, docstring и комментарии
  на русском.
- PEP 8, длина строки до 100. Аннотации типов везде.
- Каждый вызов внешней команды: с таймаутом, с `LC_ALL=C` в окружении (вывод `ufw`,
  `systemctl` и других утилит локализован, парсим только английский), с обработкой
  `FileNotFoundError` (утилиты нет) и `subprocess.TimeoutExpired`.
- Все настройки (узлы, порты, таймауты, пути) хранятся в `data/config.json`, не в коде.
- Нехватка прав — не падение, а статус `ERROR` или пометка «требуются права root»
  с понятным текстом.

## Как работать

- Работай поэтапно, по плану из SPEC.md (раздел «Порядок работы»). После каждого этапа:
  запусти тесты (`python3 -m unittest discover -s tests -v`), коротко опиши, что сделано,
  и остановись для проверки.
- Среда разработки может быть не Astra. Код, который зависит от системы, проверяется тестами
  с поддельным адаптером (`tests/fake_adapter.py`), а на настоящем стенде его запускает автор.
  Если не уверен в формате вывода утилиты на Astra, не угадывай: оставь `# TODO(стенд): ...`
  и попроси автора прислать вывод команды.
- Имена служб, пакетов и команд в `data/products.json` с пометкой `"verified": false`
  не проверены на реальной системе. Не выдавай их за точные.

## Запуск

```bash
sudo python3 main.py            # интерактивное меню
sudo python3 main.py --all      # все проверки подряд + отчёт
python3 main.py --help
python3 -m unittest discover -s tests -v
```
