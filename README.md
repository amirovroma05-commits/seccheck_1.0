# SecCheck

Консольная программа контроля работоспособности антивируса (АВ) и межсетевого экрана (МЭ)
в Linux с systemd. Выполняет четыре проверки и выводит отчёт:

1. подключение к интернету;
2. наличие АВ и МЭ;
3. работоспособность МЭ (по временному тестовому правилу, которое программа создаёт
   и удаляет сама);
4. работоспособность АВ (по тестовому файлу EICAR).

Требования: Python 3.5 или новее, только стандартная библиотека. Права root нужны
проверке 3: тестовое правило МЭ может добавить только root. Без них программа работает,
но предупреждает об этом, а проверка 3 выдаёт «не определена — нужны права root».

## Запуск при разработке

```bash
chmod +x main.py                              # один раз после клонирования
sudo ./main.py --config ./config.json         # интерактивное меню
./main.py --help
./main.py --version
sudo ./main.py --config ./config.json -v      # подробный вывод
sudo ./main.py --config ./config.json --products my-products.json   # другой список продуктов
```

Каждая проверка отвечает только на свой вопрос, и по умолчанию вывод краткий: строка итога
«<Название>: <результат>», под ней — только то, что отвечает на тот же вопрос (найденные
продукты в проверке 2), и подсказка, если результат не OK:

```
[  OK  ] M1  Подключение к интернету: есть
[ WARN ] M2  Наличие АВ и МЭ: найден только межсетевой экран
         Антивирус:          не найден
         Межсетевой экран:   ufw
[ FAIL ] M3  Работоспособность МЭ: запрещённое соединение не заблокировано
         Проверьте, что межсетевой экран включён
[  OK  ] M4  Работоспособность АВ: тестовый файл обнаружен за 2 с (файл удалён)
```

Флаг `-v` (`--verbose`) добавляет под каждой проверкой подробности: ответы узлов, найденные
файлы и службы продуктов, проверяемый МЭ и команду тестового правила, адреса и время
подключений, путь к тестовому файлу. Отчёт (пункт 6 меню) печатается в том же виде.

Без `--config` программа ищет `/etc/seccheck/config.json`, который появляется только после
установки (см. «Настройки»).

## Установка и обновление

```bash
sudo ./install.sh                 # установка в /opt/seccheck и команда seccheck
sudo seccheck                     # запуск после установки
git pull && sudo ./install.sh     # обновление
sudo ./uninstall.sh               # удаление
```

`install.sh` копирует файлы `*.py`, `products.json` и образец `config.json`
в `/opt/seccheck` (владелец root, каталог 755, файлы 644) и создаёт обёртку
`/usr/local/bin/seccheck`. При повторном запуске старая версия программы удаляется целиком
и устанавливается заново. Файл настроек `/etc/seccheck/config.json` создаётся только при
первой установке и потом никогда не перезаписывается (см. «Настройки»). `uninstall.sh`
удаляет программу, но оставляет `/etc/seccheck`.

### Почему программа ставится в каталог, доступный на запись только root

Программа запускается от root. Если бы её файлы лежали в каталоге, куда может писать
обычный пользователь (например, в домашнем каталоге), любой процесс этого пользователя,
в том числе вредоносный, мог бы незаметно изменить код. При следующем запуске через `sudo`
изменённый код выполнился бы с правами root, то есть получилось бы повышение привилегий.
Поэтому установленная копия лежит в `/opt/seccheck`, а она и обёртка
`/usr/local/bin/seccheck` принадлежат root и закрыты от записи остальным. Обёртка
вызывает интерпретатор по полному пути `/usr/bin/python3`, чтобы его нельзя было подменить
через `PATH`. Запуск из рабочей копии (`sudo ./main.py`) годится только для разработки.

## Настройки

Узлы, порты и таймауты проверок хранятся в файле настроек, значений по умолчанию в коде
нет. Без файла программа не запускается.

- По умолчанию используется `/etc/seccheck/config.json`. Его создаёт `install.sh` при первой
  установке из `config.json` проекта; повторная установка файл не перезаписывает, а только
  проверяет и сообщает об ошибках. Образец текущей версии лежит в
  `/opt/seccheck/config.json` — с ним удобно сравнивать после обновления.
- Флаг `--config ПУТЬ` задаёт другой файл. При разработке:
  `sudo ./main.py --config ./config.json`.
- Использованный файл указывается в заголовке отчёта. При ошибке в файле программа
  сообщает файл, секцию и ключ и завершается с кодом 2.

Все секции и ключи обязательны; неизвестные секции и ключи считаются ошибкой (так ловятся
опечатки). Таймауты и интервалы — в секундах, больше 0 и не больше 300.

| Секция | Ключ | Значение | Проверка |
|---|---|---|---|
| `network` | `ru_hosts` | российские узлы, например `["ya.ru", "vk.com"]` | 1 |
| | `foreign_hosts` | зарубежные узлы, например `["example.com", "github.com"]` | 1 |
| | `tcp_port` | порт TCP-подключения (443) | 1 |
| | `tcp_timeout_s` | таймаут одного TCP-подключения (3) | 1 |
| | `ping_timeout_s` | ожидание ответа на ping (2), **только целое**: его получает `ping -W` | 1 |
| `presence` | `cmd_timeout_s` | таймаут одной команды `systemctl` (5) | 2 |
| `firewall_test` | `host` | узел для проверки МЭ (`ya.ru`) | 3 |
| | `test_port` | порт, соединения на который запрещает тестовое правило (80) | 3 |
| | `timeout_s` | таймаут одного подключения и одной команды `ufw` или `systemctl` (3) | 3 |
| `antivirus_test` | `eicar_dir` | `null` — системный временный каталог; иначе абсолютный путь к существующему каталогу | 4 |
| | `eicar_timeout_s` | сколько ждать реакции АВ (30) | 4 |
| | `poll_interval_s` | как часто проверять тестовый файл (1) | 4 |

Внутри `eicar_dir` программа создаёт свой подкаталог `seccheck_…` и после проверки удаляет
только свой файл и этот подкаталог; сам `eicar_dir` и всё остальное в нём не трогает.

### Как поменять список узлов

Отредактируйте списки `ru_hosts` и `foreign_hosts` в `/etc/seccheck/config.json`
(`sudo nano /etc/seccheck/config.json`). В каждом списке должен быть хотя бы один узел;
проверка 1 считает группу доступной, если ответил хотя бы один её узел. Изменения действуют
при следующем запуске.

Имена узлов (латинские буквы, цифры, точка и дефис, первый символ — буква или цифра,
до 253 символов) проверяются потому, что они передаются команде `ping`, запущенной от root:
имя вроде `-c100` она приняла бы за свой ключ, а не за адрес.

## Список продуктов

Проверка 2 ищет известные средства защиты по описаниям из файла `products.json`: продукт
найден, если есть хотя бы один его файл или установлена хотя бы одна его служба. Если
службы продукта установлены, но ни одна не запущена, после названия пишется «(служба
остановлена)». Включена ли защита, проверка 2 не выясняет — это делают проверки 3 и 4. По
умолчанию берётся файл, лежащий рядом с `main.py` (после установки —
`/opt/seccheck/products.json`). Файл читается один раз при запуске; если в нём ошибка,
программа сообщает, в каком продукте и в каком поле, и не запускается (код выхода 2).
Использованный файл указывается в заголовке отчёта.

### Формат

```json
{
  "products": [
    {
      "id": "clamav",
      "name": "ClamAV",
      "kinds": ["antivirus"],
      "services": ["clamav-daemon"],
      "files": ["/usr/sbin/clamd"],
      "verified": false,
      "notes": "Имена служб и путей не проверены на стенде"
    }
  ]
}
```

| Поле | Обязательное | Значение |
|---|---|---|
| `id` | да | уникальный идентификатор (строка) |
| `name` | да | название для отчёта |
| `kinds` | да | непустой список из `"antivirus"` и `"firewall"` |
| `services` | да | службы systemd (может быть пустым): любая установлена → продукт найден |
| `files` | да | абсолютные пути (может быть пустым): любой файл есть → продукт найден |
| `verified` | нет | имена служб и пути проверены на реальной системе; по умолчанию `false`. Если `false` и продукт не найден, в подробном выводе (`-v`) пометка «профиль не проверен на стенде»: возможно, продукт есть, а имена неверны. У найденного продукта пометки нет — его имена подтвердились |
| `notes` | нет | примечание для себя, в отчёт не выводится |

Полей `protection_service` и `active_if_filtering` из прежних версий больше нет: файл
продуктов с ними не загрузится (ошибка «неизвестное поле»), их нужно удалить.
Имена служб: латинские буквы, цифры и символы `@ . _ -`, первый символ — буква или цифра.
Неизвестные поля и повторяющиеся `id` считаются ошибкой: так ловятся опечатки.

### Как добавить свой продукт

1. Скопируйте файл: `cp /opt/seccheck/products.json ~/my-products.json`.
2. Добавьте в список `products` объект с полями из таблицы. Имя службы узнайте командой
   `systemctl list-unit-files | grep <название>`, путь к файлу — `command -v <программа>`
   или из документации продукта.
3. Запустите программу со своим файлом:

   ```bash
   sudo seccheck --products ~/my-products.json
   ```

Чтобы изменить список по умолчанию, отредактируйте `products.json` в проекте и выполните
`sudo ./install.sh`.

Файл читает программа с правами root, поэтому в формате нет полей с командами: имена
служб только передаются в `systemctl show` отдельным аргументом, а пути только
проверяются на существование, так что подменённый файл может исказить результат
проверок 2 и 3, но не заставит программу выполнить свою команду. Команды тестового
правила МЭ заданы в коде (`check_firewall.py`), из файла продуктов берётся только `id`.

## Подготовка стенда

Команды даны для дистрибутивов на базе Debian (`apt`). В других дистрибутивах установите
те же пакеты своим пакетным менеджером. Имена пакетов и служб проверьте в своей системе.

### ClamAV с проверкой при доступе (clamonacc)

```bash
sudo apt install clamav clamav-daemon
sudo systemctl stop clamav-freshclam && sudo freshclam && sudo systemctl start clamav-freshclam
```

В `/etc/clamav/clamd.conf` добавьте:

```
OnAccessIncludePath /tmp
OnAccessPrevention yes
OnAccessExcludeUname clamav
```

- `OnAccessIncludePath /tmp` — проверка 4 создаёт тестовый файл во временном каталоге
  (`/tmp`), clamonacc следит только за указанными каталогами. Если задан
  `antivirus_test.eicar_dir` (см. «Настройки»), укажите здесь этот каталог;
- `OnAccessPrevention yes` — блокировать доступ к заражённому файлу, а не только писать
  в журнал;
- `OnAccessExcludeUname clamav` — не проверять действия самого ClamAV.

Перезапустите службы:

```bash
sudo systemctl restart clamav-daemon
sudo systemctl enable --now clamav-clamonacc   # имя службы проверьте: systemctl list-unit-files | grep clam
```

### ufw

```bash
sudo apt install ufw
sudo ufw allow ssh        # если работаете по SSH, иначе после включения связь пропадёт
sudo ufw enable
sudo ufw status verbose
```

## Проверка 3: тестовое правило МЭ

Проверка 3 ничего не требует от проверяющего: временное тестовое правило она создаёт
и удаляет сама.

1. Находит МЭ, который умеет проверять (сейчас только ufw), тем же способом, что
   проверка 2. Для Dr.Web и KESL способ проверки не задан: проверка 3 выдаёт «не определена».
2. Подключается к узлу `host` (по умолчанию `ya.ru`) на порт `test_port` (80) — порт
   должен быть доступен.
3. Добавляет через ufw правило, запрещающее исходящие TCP-соединения на IP-адрес этого
   узла и этот порт, с меткой `seccheck-test`:
   `ufw insert 1 deny out to <IP> port 80 proto tcp comment seccheck-test`.
   Правило ставится первым, чтобы его не перекрыли разрешающие правила пользователя
   (если правил ещё нет, то обычным `ufw deny out …`).
4. Подключается ещё раз. Не удалось — «запрещённое соединение заблокировано» (`OK`),
   удалось — «запрещённое соединение не заблокировано» (`FAIL`): ufw выключен или
   не применяет правила. При выключенном ufw правило сохраняется в его настройках, но
   не действует, поэтому результат честно `FAIL`.
5. Удаляет правило в любом случае, в том числе после Ctrl+C, `kill` (SIGTERM) и закрытия
   терминала (SIGHUP):
   `ufw delete deny out to <IP> port 80 proto tcp comment seccheck-test`.
   Удаляется только правило с меткой `seccheck-test`; правила пользователя, в том числе
   его собственное `deny out 80/tcp`, не затрагиваются. Если удалить не удалось, программа
   печатает «Внимание: тестовое правило не удалено» и точную команду удаления.

Если порт закрыт ещё до добавления правила (например, есть правило пользователя
`deny out 80/tcp`), проверка 3 выдаёт «не определена — тестовый порт недоступен ещё до
проверки»: по такому порту работу МЭ проверить нельзя. Правило, оставшееся от прежней
версии программы, удалите: `sudo ufw delete deny out 80/tcp`.

### Если программа была убита (kill -9, отключение питания)

После `kill -9` или отключения питания программа не успевает удалить правило. Найдите его
по метке `seccheck-test`:

```bash
sudo ufw status | grep seccheck-test       # при включённом ufw
sudo ufw show added | grep seccheck-test   # сохранённые правила, в том числе при выключенном ufw
```

`ufw show added` выводит правило в виде команды, например
`ufw deny out to 87.250.250.242 port 80 proto tcp comment 'seccheck-test'`.
Удалите его той же командой с `delete` после `ufw`:

```bash
sudo ufw delete deny out to 87.250.250.242 port 80 proto tcp comment seccheck-test
```

Подставьте адрес и порт из найденной строки. Затем убедитесь, что правила нет:
`sudo ufw show added | grep seccheck-test` ничего не выводит.
